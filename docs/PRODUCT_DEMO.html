The problem / Who feels it

Small teams ship software.
Security expertise does not ship with it.

Solo developers and early-stage startups need an accessible first security check before deployment.

Knowledge gap

Which checks matter? How do we test authentication, dependencies and browser behavior?

Fragmented workflow

Free tools exist, but installing several engines and interpreting different outputs takes effort.

Real cost

Time away from building, paid-tool or specialist budgets, and rework when issues surface late.

Our opportunity: reduce setup and interpretation friction, not claim that existing security tools are all paid.

Customer hypothesis: teams will value one guided release-check workflow. Time savings, willingness to pay and adoption still need validation.

One main flow / From running app to action

Configure once. Scan. Review. Improve.

1

Start your app
Frontend and backend run in separate terminals.

2

Run securerelease init
Enter UI/API URLs, OpenAPI spec, source folder and test credentials.

3

Run securerelease run
Execute the configured checks and write one HTML report.

4

Review evidence, fix, rerun
Start with coverage gaps and high-impact findings.

  • Compare evidence, not just finding counts.
  • Show authentication, headers, ownership and rate-limit signals.
  • Keep inherited dependency issues visible.

Same default report path: reports/securerelease-report.html. The next run overwrites it.

Engineering tradeoffs / Trust over a green badge

Useful coverage without unsafe defaults.

Build vs. integrate

Compared: write every security engine or wrap established tools.

Choice: integrate Trivy, Gitleaks and Semgrep; build UI/API checks.

Tradeoff: faster breadth, but engine installation and output normalization remain necessary.

Crawler vs. browser

Problem: a plain HTTP crawler cannot see React-rendered login forms.

Choice: Playwright for JavaScript UIs; keep the lightweight crawler.

Tradeoff: better rendered-page coverage, but browser setup and runtime cost.

Coverage vs. safety

Compared: probe every method or require explicit authorization.

Choice: gate active tests and writes; never send DELETE.

Tradeoff: some checks remain skipped. Report that honestly rather than mark them PASS.

Reliability improvement: browser login now waits for the password form to disappear and checks that the session survives a target reload.
Readiness checks, not a penetration test or security certification05 / 06
